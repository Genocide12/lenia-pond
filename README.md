# Пруд Лении

Пруд из тысяч квадратов-блюдцев, в каждом — своя жизнь и свой климат.
Зум от одного блюдца до всей сетки 64×64 (до 4096 блюдцев): грибы делятся
на колонии, головастики гибнут в жарких блюдцах, жуки плодятся в тепле.

Реконструкция оригинальной [Lenia](https://github.com/Chakazul/Lenia)
Бёрта Ван-Чака Чана (Python/animals.json) на WebGL2.

**Живая версия:** <https://genocide12.github.io/lenia-pond/>

## Приложение

Пруд — PWA: работает офлайн и устанавливается на домашний экран.

- **Android / Chrome, Edge**: кнопка «Установить приложение» (иконка со стрелкой) или «Установить» в меню браузера.
- **iPhone / Safari**: «Поделиться» → «На экран “Домой”».
- **Windows / macOS / Chrome**: значок установки в адресной строке.

После установки пруд открывается отдельным окном без адресной строки,
как настоящее приложение.

## Управление

| Действие | Телефон | Компьютер |
| --- | --- | --- |
| Зум | щипок двумя пальцами | колесо мыши к курсору |
| Панорама | перетаскивание | перетаскивание, стрелки/WASD |
| Перелёт к блюдцу | тап по блюдцу вдалеке | клик |
| Поселить существо | тап крупным планом | клик крупным планом |
| Зум по месту | двойной тап | двойной клик |
| Пауза | кнопка ⏸ | пробел |
| Скорость ×1…×100 | кнопка ×N | ×N или клавиши 1–6 |
| Весь пруд | кнопка ⛶ | 0 |
| Пересадить блюдце | — | R |

Кнопка с термометром открывает климат наблюдаемого блюдца: холодные
и жаркие края губительны для большинства видов, умеренная середина —
зона жизни. Полоса видов внизу выбирает, кого сажать.

## Блюдца и условия

Каждое блюдце — изолированный тор 96×96 клеток с собственной физикой
Lenia и своим климатом, сдвигающим параметры роста. Счётчик существ
использует периодическую связность (union-find через край тора блюдца):
существо, пересекающее границу, остаётся одним целым.

## Производительность

- **Инстансированные шаги**: все видимые блюдца шагают за ОДИН пару
  draw call (WebGL2 instancing + атлас ядер) — стоимость CPU не растёт
  с числом блюдц, кадр держит только свёртка на GPU.
- **Асинхронные чтения**: пробы масс (LOD) и анализ блюдца в фокусе —
  через PBO-кольцо с fence sync: ни одного синхронного readPixels
  в кадре, конвейер GPU не останавливается.
- **Кэш слотов**: при выходе блюдца из зоны детализации его жизнь
  не стирается — слот держится ещё несколько тиков, и при возврате
  камеры колония продолжается с того же места (без пересева).
- **Ноль аллокаций в кадре**: пулы объектов, переиспользуемые массивы
  и буферы — новые данные затирают старые, GC не фризит анимацию.
- Мип-уровни мета-текстуры перестраиваются не чаще 7 раз/с, LOD —
  только когда атлас реально менялся.
- Стоимость кадра не зависит от зума: за кадр выполняется не больше
  `budget` шагов (адаптируется по времени кадра). Весь пруд рисуется
  одним проходом в шейдере; на мобильных разрешение рендера
  ограничено (dpr ≤ 1.5). На больших скоростях (×50, ×100) движок
  честно выжимает максимум из устройства — темп ограничен только GPU.

## Проверка корректности

- `bun run lint` — чисто.
- `scripts/verify_pond.py` (NumPy, та же арифметика): все 11 видов
  выживают в блюдце 96×96; свип климата `verify_climate.py` — карта
  «климат → (m, s)».
- `scripts/verify_precision.py`: зеркала и повороты не влияют на деление;
  шум выше 1e-4 ломает колонию — поэтому атлас хранится в R32F.
- `scripts/verify_f32.py`, `verify_ecotype2.py`: в чистом float32
  (точность GPU) исходный гриб образует колонию лишь в ~30% прогонов —
  поэтому в пруду живёт экотип с s×1.1 (0.0396): колония 22–27 организмов
  в 100% прогонов. Вживую в WebGL: t≈440, 21 организм, масса 3029.
- Пошаговая сверка WebGL ↔ NumPy: масса гриба совпадает до сотых
  на каждом из первых шагов (622.07 → 622.57 → …).
